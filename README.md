# Minimal match and SNR loss from imperfect templates

**Claim.** How imperfect a template must be to lose a signal — recovered matched-filter
SNR below the detection threshold — and how dense a template bank must be so that never
happens, derived from the match metric and verified with injections.

**Scope (v1).** Non-spinning 2-parameter bank in $(m_1, m_2)$, single detector,
$\sim 5$–$50\,M_\odot$. Detection threshold from an analytic Gaussian false-alarm rate.
Numeric match metric checked against the analytic Owen metric (TaylorF2). Monte-Carlo
covering check at minimal match 0.97. Output: fractional volume loss and template count
as a function of minimal match, and whether the textbook $\Delta V/V \approx 3(1-\mathrm{MM})$
rule holds where the metric varies fastest.

**v2, if time allows.** Replace the analytic threshold with a false-alarm rate measured
from real non-Gaussian off-source data.

Final project for *Gravitational Waves and AI-Assisted Research*. This repository is the
machine-facing half: it is meant to be reproduced by an agent from a clean clone. The
human-facing half is `page/index.html` and `paper/main.pdf`.

## How to reproduce

```
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python scripts/compute_numbers.py      # writes data/project_numbers.json (the number registry)
python scripts/make_figures.py         # writes figures/*.pdf
python scripts/check_provenance.py     # the gate: every number and figure has a record
```

Every file that is produced rather than tracked has a rebuild command in
[`wiki/reproducibility.md`](wiki/reproducibility.md). If a local file is not tracked and
not listed there, that is a bug in this repository.

Adapted from the day-5 "a paper published as a repository" pattern.

| path | what it holds | who writes it |
|---|---|---|
| `src/` | importable modules: the overlap, the match metric, the bank, the threshold | by hand |

| `scripts/make_figures.py` | every figure, one function per panel | by hand |

| `data/` | numeric inputs and the number registry `project_numbers.json` | scripts only |
| `structure/claims.yaml` | the argument skeleton: each claim → section, numbers, evidence | by hand |
| `figures/` | every figure, regenerated by `scripts/make_figures.py` | scripts only |
| `results/` | large intermediates (`*.npz`), **untracked** — rebuild via `wiki/reproducibility.md` | scripts only |
| `paper/` | the PDF deliverable: `main.tex` + `sections/`, with `\dataref` / `\genby` provenance macros | by hand |
| `page/` | the HTML deliverable | by hand |
| `provenance/numbers.json` | every number reported anywhere, with what produced it and every choice | agent + by hand |
| `provenance/claims.yaml` | what is asserted, the evidence, and every figure left behind | agent + by hand |
| `wiki/` | the working knowledge base — **derived**; read before answering, write back into | agent + by hand |
| `.claude/`, `.codex/` | the provenance convention (stated once), the skill that points at it, and the `Stop` gate | — |

The split is deliberate: `page/` and `paper/` are for a person; everything else is for a
machine reproducing the result.

## Reproducibility — what is claimed, and what is not

Modelled on the day-5 release README. This does **not** say the repository is
"reproducible" without qualification. It says, in named categories, what was measured and
how — and the last category is a thing it does not claim. Each line is filled in as the
work is done, and each is checkable by running the thing, not by taking it on trust.

1. **Bitwise, demonstrated.** `data/project_numbers.json` regenerates byte-identically
   from `scripts/compute_numbers.py` on the reference platform. *(to be demonstrated)*
2. **Raster-identical, not byte-identical.** The figure PDFs regenerate with zero
   differing pixels at 200 dpi but not byte-for-byte, because matplotlib stamps
   `/CreationDate` and `/Producer`. Fix: set `SOURCE_DATE_EPOCH` to a fixed value with a
   pinned matplotlib. *(to be demonstrated)*
3. **Within a stated, measured tolerance.** Numerical tests compare at a fixed fraction
   of each array's own scale; the tolerance is measured against a second BLAS build
   rather than chosen. *(to be measured)*
4. **Within tolerance, not bitwise.** Monte-Carlo products (the covering check, any
   sampled efficiency) agree only to Monte-Carlo error; every number quoted is rounded
   well inside it. *(to be stated)*
5. **Not claimed.** That any large `results/*.npz` array reproduces byte-for-byte on a
   different platform. The pipeline is how they were made; the deposited arrays, if any,
   are what the result used.

## Provenance discipline

Carried over from day 5. Work that produced a figure or a number is not finished until
the record exists.

- The format is stated once in `.claude/provenance/{numbers,claims,figures}.md`.
- The `provenance-record` skill points a fresh session at those files.
- A `Stop` hook (`.claude/hooks/provenance_gate.py`, wired for Claude Code in
  `.claude/settings.json` and for Codex in `.codex/hooks.json`) checks, at the moment the
  agent decides it is finished, that every figure and number left behind has an entry —
  and on failure hands back the convention file that applies.
- Codex will not run the hook until it is trusted in `/hooks`.
